This folder is for building an agentic OS, right, and should have everything that is on focussed on building this product.

## Project map (Nova)
- `packages/core` - DecisionEngine (System 1: Reflex - Nova's own local model, the default - plus Jev called directly (`decision/jev.ts`: `POST api.typesafe.ai/v1/systemone`, `NOVA_JEV_API_KEY`; only when chosen, Reflex as its fallback; `decision/handoff.ts` reads its answers as Reflex would: a restated action is a yes, and skill picks under `JEV_DOUBT_FLOOR` (0.8, chosen on sets A/B/D) go to the brain when there is one), a model on the user's own server, offline heuristic). There is no gateway: a model id never goes to the AI SDK's default provider (`LocalLanguageModel`), NovaBrain orchestrator, skills, guardian (risk tiers), wire protocol.
- Reflex (`packages/core/src/decision/reflex/`): static embeddings (Model2Vec potion-base-8M, pure TS); closest-example search over `phrases.ts` with names masked, plus a softmax classifier (`head.ts`) on the word meanings and - with its sentence model installed (MiniLM L6, `all-MiniLM-L6-v2` via transformers.js in `apps/daemon/src/reflex/sentence-worker.ts`, a `SentenceEncoder`) - on how MiniLM reads the whole utterance; then it may lift a match over the brain's floor only when the classifier and the examples pick the same intent (`SENTENCE_TUNING`). Replies are read in code for every engine (`decision/replies.ts`, applied by `EvaluationDecisionEngine`). The classifier is trained on `phrases.ts` + `grammar.ts` + learned examples (the daemon trains it in the background and caches it in `~/.nova/reflex-classifier.json`, keyed by a fingerprint of its data); name matching in code, context priors, learning from confirmations and from the brain (one successful non-`informs` skill call while answering a handed-off utterance). New skills need phrasings in `phrases.ts` (a test checks) and ideally patterns in `grammar.ts`. Model files are downloaded by `apps/daemon/src/models/files.ts` (pinned revision + checksums) to `~/.nova/models`; measure changes with `npm run reflex:eval` (it holds every test phrasing out of training - short ones too, except universal replies - and counts wrong app/agent/project names). Sets A, B, D in `evalSet.ts` are for development; C and E are held out - never tune to them.
- `apps/daemon` - local WebSocket service (127.0.0.1:7878), macOS app control, `jev:ping` latency spike.
- `apps/daemon/src/agents` - agent pairing: presets run each vendor's official CLI (`claude -p`, `codex exec`, `opencode run`, `gemini`) on the user's own login, custom agents via `nova.agents.json`; Claude's permission prompts reach the user's voice through `approval-mcp.mjs`. `models.ts` resolves `<provider>/<model>` ids for local servers (LM Studio, Ollama, oMLX, ...).
- Agent rules: agents work only in configured project folders (never a path from speech); strip API-key env vars so agents bill the user's plan; never use the Agent SDK or `--bare` with subscription logins.
- Tools: NovaBrain is the ToolHost (`specs()`/`call()` in `packages/core/src/brain/nova.ts`): skills become tools (`skills/tools.ts`), gated by the skill's own tier. Agents reach them over MCP through `apps/daemon/src/agents/bridge.ts` + `nova-mcp.mjs` (per-hookup token); each preset attaches them its CLI's way. Brains stream (`ReasoningBrain.stream`) and NovaBrain speaks finished sentences as `say` events with one `id` (`partial` until the end); Claude runs as a kept-alive `AgentSession`.
- Settings: user settings live only in `~/.nova/settings.json` (nested JSON, e.g. `voice.rate`); `packages/core/src/settings.ts` is the schema (keys, defaults, validation) - add a field there and read it in `loadConfig` in `apps/daemon/src/config.ts`. `.env` holds constants only (port, UI origins, file paths, API keys); never add user settings to it. The daemon applies changes live (Settings window or hand edits to the file) via `NovaBrain.reconfigure`; secrets never leave the daemon.
- Voice: Kokoro is Nova's only voice (no system voices). `apps/daemon/src/voice/tts.ts` speaks replies with it (kokoro-js, fp32 model, voices bundled in the package) and streams 16-bit PCM per sentence as `audio` events; Nova.app or the window plays them (`speakStream` in `voice.ts`); without Kokoro, replies are shown, not spoken. The model is bundled into Nova.app's `Contents/Resources/models` by `npm run app` (`bundleModel`; the app passes `NOVA_BUNDLED_MODELS` to its daemon, a terminal daemon looks in `~/Applications/Nova.app`); `whereInstalled` checks `~/.nova/models` first. Model downloads go through `apps/daemon/src/models/files.ts` (pinned revision, checksums, streamed to disk).
- Hearing: the window streams its mic (16 kHz PCM, binary WebSocket frames after `audio-start`; `startCapture` + `public/capture-worklet.js`) to `apps/daemon/src/hearing/service.ts`, which runs speech detection and turn-taking (`SpeechActivity`/`TurnDetector` in `packages/core/src/speech.ts`, plus Smart Turn in `turn-worker.ts`; with `hearing.speechOnly`, Silero VAD in `speech-worker.ts` gives its say on each 32 ms and only a voice counts, falling back to loudness if it stops) and relays audio to the Swift helper `apps/daemon/native/hearing` (Apple SpeechAnalyzer with a fresh session per turn, or Parakeet via FluidAudio). Finished turns go to `NovaBrain.handle`; talking over Nova sends `barge-in` and calls `NovaBrain.interrupt()` (pending questions survive). `build.ts` builds the helper (FluidAudio at a pinned commit, without its prebuilt NeMo binary); `NOVA_HEARING_DEBUG=1` makes the helper log recognizer results to stderr.
- Voice ID: three models make voiceprints of each turn - the hearing helper's (`native/hearing/Sources/Voice.swift`: WeSpeaker v2 through FluidAudio's `EmbeddingExtractor`, model `wespeaker-v2`; `--voice-selftest`) and two in ONNX Runtime in their own process (`voice-worker.ts` via `printer.ts`: WeSpeaker ResNet293 and NVIDIA TitaNet-Large, sherpa-onnx exports from its GitHub release, pinned by SHA-256; their features - Kaldi fbank, NeMo log-mel - in code in `features.ts`). `apps/daemon/src/hearing/voiceid.ts` holds the arithmetic (voiceprint v3: each model's print, centroids and bars; `scoreOf` places each model's match between its own bars and weighs them by `EAR_WEIGHTS`; `enrollFrom`, `judge` you / not-you / unsure, `learnFrom` only for clear long turns; the user's clear turns of the last 10 minutes count too, less a margin) and `~/.nova/voiceprint.json` (0600). `recordings.ts` keeps each checked turn's audio and scores in `~/.nova/voice-recordings/` only when `voiceId.keepRecordings` is on (7 days, 0600; switching it off deletes them) - for tuning the weights on the user's own voice. `Hearing` asks for each finished turn's print (`VoiceCheck`) and passes `speaker` to `NovaBrain.handle`: `not-you` is ignored entirely (before the wake word opens anything), `unsure` gets the talk-shortcut hint; shortcut turns and typing count as the user, browser-recognised speech doesn't. Settings `voiceId.enabled` / `voiceId.learn` / `voiceId.keepRecordings`.
- Integrations: `packages/core/src/integrations.ts` (entries, presets, per-tool policy) and `apps/daemon/src/integrations/` - `mcp.ts` (a small MCP client: stdio, Streamable HTTP, legacy SSE), `oauth.ts` (MCP authorization: discovery, dynamic registration, PKCE; tokens in `~/.nova/integration-tokens.json`, 0600), `hub.ts` (connections, reconnects, tools as `<server>__<tool>`). NovaBrain offers them to every brain next to the skills and gates each call by `policyTier`: the tier comes from the user's settings (ask always / changes / never, per-tool allow/ask/block), never from the service or the caller - server read-only labels count only under "changes". Secrets in integration entries are `${NAME}` references to .env (validation rejects pasted tokens). The OAuth redirect is the daemon's own `/oauth/callback` on its port.
- Memory & screen: `packages/core/src/skills/memory.ts` (remember / recall / forget, search_conversations tool-only) and `skills/screen.ts` (look_at_screen, tool-only); `apps/daemon/src/memory/store.ts` (`~/.nova/memory.json` + `~/.nova/conversations/YYYY-MM-DD.jsonl` by local day, 0600) and `src/screen/eyes.ts` + `native/eyes` (Nova Eyes: its own LSUIElement app in `~/.nova/apps`, so TCC grants go to it; Unix socket answering only the parent pid). Nothing is saved silently: `remember`'s tier comes from `tierFor` - the user's own words (`SkillContext.heard`, empty for an agent working on its own) - never the brain's request. Notes (context + related memories) are prepended to brain questions, never stored in history. `declines` lets a skill hand a misheard utterance to the brain.
- Trust: `packages/core/src/skills/trust.ts` (undo, activity report, stop everything, permissions; `alwaysIn`, `RISKY_COMMAND`) and `apps/daemon/src/trust/` - `actions.ts` (the record, `~/.nova/activity/YYYY-MM-DD.jsonl`, undo steps kept daemon-side, windows never see them), `undo.ts` (one `UndoStep` back), `snapshots.ts` (git trees with a temporary index under `refs/nova/snapshots`; undo refuses if the user changed those files since), `rules.ts` ("yes, always" in `trust.rules.<id>` of the settings file: only from the user's words, never for risky commands), `privacy.ts` and `setup.ts` (the privacy page and setup checklist, computed from the settings in effect). Skills that change something return `undo` in their result; ones worth "always" declare `rememberAs`.
- Doing what's said - Permissions (`trust.mode`, Settings → Privacy & trust, never changed by voice; `PermissionMode` in `guardian.ts`): `ask` asks before every change; `auto` (the default) does a tier-2 request the user made without a yes - by voice (`route`, still needing tier 2's confidence) and for a brain's steps while answering a request to act (`toldTo`: `asksToAct(heard)`, never for an agent's own task) - and asks about the rest; `free` asks nothing, of anyone (Nova's skills, a brain's own steps, agents' commands via `requestApproval`, integrations' tools). `trust.stillAsk` (default on) keeps `Skill.weighty` (money, what can't be taken back; content can only add one), tier 3 (a tap) and an agent's `RISKY_COMMAND` asked in every mode, over any rule. Tier 3 is asked with a card marked `tap` (`TAP_BODY`/`TAP_SAY` in nova.ts) that a spoken yes never answers - only `NovaBrain.tapAnswer` (the `tap-answer` client event: Allow in Nova's window, or Allow with Face ID on a paired iPhone, `LocalAuthentication` before it's sent); a no, spoken or tapped, refuses. `trust.alwaysForGood` (default on) keeps "yes, always" for good whatever it was said to (`ruleFor`: a skill's `rememberAs`, else its `session` key - `computer` for every screen step - else `skill:<id>`; a service's changing tool; an agent's risky command or whole tool); off, those are only for the task or asked each time. The brain's system prompt (`voiceSystemPrompt(assistant, mode)`) says what to do about asking; agents' sessions restart when the mode changes (`agentsKey`). A settings file's old `trust.askFirst` still reads as `ask`.
- Hands: parsers in `packages/core/src/hands.ts` (settings, media, windows, files, clipboard, Shortcuts, "click send"); skills in `skills/hands.ts` (system_control, media_control, window_control, files, clipboard, run_shortcut, ui_control, computer_task) and `skills/computer.ts` (computer_look/click/type/key/scroll/drag: tools for brains); the daemon's `src/hands/` implements `HandsService` (`system.ts`, `media.ts` via osascript + media keys, `windows.ts`, `files.ts`, `shortcuts.ts`, `computer.ts` = `ComputerService`: look/act/preview, waits while the user types, `hands.maxSteps`), and Nova Eyes does the AX/CGEvent/ScreenCaptureKit work (`native/eyes/Sources/Act.swift`, `Keys.swift`, `Windows.swift`, `System.swift`, `Files.swift`, `Highlight.swift`). Tier 1 only when the user's own words asked for that same thing (`userAsked` over `heard`), otherwise asked; `prepare` finds the thing before the tier and the question (the file "the invoice" is); `preview` frames the target while asking; `session` + `taskScope` = "go ahead with all of it" for one task, never stored. Agents at work get Nova's tools through `bridge.task()` (one nova-mcp with the approval and tools tokens). Undo steps: `system-set`, `media`, `windows-restore`, `file-move`, `file-untrash`, `clipboard-set`. Settings `hands.*`.
- Signing: `apps/daemon/src/shell/signing.ts` signs Nova.app (`install.ts`), Nova Eyes (`screen/eyes.ts`) and the hearing helper (`hearing/build.ts`) - with the user's Apple certificate when there is one (found by itself; `NOVA_SIGN_IDENTITY` in .env overrides, `-` = ad hoc), hardened runtime, entitlements in `apps/desktop/macos/Nova.entitlements` and `apps/daemon/native/eyes/Eyes.entitlements`, and a designated requirement pinned to the app id and the team (`anchor apple generic and certificate leaf[subject.OU] = TEAM`), so TCC grants survive rebuilds and renewals. Built apps are re-signed when the identity changes (`needsSigning`). Nova Eyes answers only a client whose parent is Nova.app of the same team (`native/eyes/Sources/Lock.swift`; else `not-nova-app` and it quits), so Nova.app runs the daemon as its direct child (tsx's loader in-process, `DaemonHost.swift`). Settings → System and the setup checklist show the state (`signingStatus`).
- iPhone (Settings → iPhone, `phone.*`): `packages/core/src/phone.ts` (the door's protocol: pairing link, challenge, close codes) and `qr.ts` (QR codes in code); `apps/daemon/src/phone/` - `door.ts` (TLS WebSocket on every network, open only while `phone.enabled`; the phone pins its certificate from the pairing QR code, then signs a challenge with its Secure Enclave key), `devices.ts` (`~/.nova/phone/devices.json`, 0600), `tls.ts` (made with macOS's openssl), `bonjour.ts` (`_nova._tcp` via dns-sd). Away from home the phone reaches the Mac through Tailscale: `reachableAddresses` gives the Wi-Fi's addresses, then the tailnet's (`isTailnet`, 100.64.0.0/10) while `phone.anywhere` is on - in the pairing link and in every `phone-welcome` (`hosts`, which the phone keeps, so a tailnet set up after pairing is known); off, the door refuses connections that came in on a tailnet address (`DOOR_CLOSE.away`, and the phone drops that address). The phone's `Door` tries every way at once (Bonjour, each address) and takes the first in. Phones are clients like windows but get only `PHONE_EVENTS` and may send only `PHONE_MAY` (server.ts); a phone's talk button takes the microphone (`micBefore`), and Nova's voice is in one place at a time (`apps/daemon/src/voice/place.ts`, `VoicePlace`): a reply is said where it starts - the phone the user is talking on (however long Nova thinks about what was said into it, `PHONE_THINK_MS`, and 90 s after), else the Mac - all of it there (a phone that goes halfway doesn't hand the rest to the Mac), and everyone else gets `barge-in` as it starts. The phone, waiting for an answer out of the front, keeps itself awake with silence on its speaker (`Voice.stayAwake`: mixed with other audio, ducking only once Nova speaks), so the answer is said there when it comes; a line lost mid-reply ends the reply with what came (`Voice.streamLost`). The app is `apps/ios` (SwiftUI, iOS 26+): a hand-written Xcode project whose `Nova/` folder is synchronized (new files need no project edit); `Link/Door.swift` (Bonjour, the pinned TLS, the signed challenge, reconnecting), `Voice/` (the microphone while the talk button is held, Kokoro's audio; `PhoneHearing` = SpeechAnalyzer on the phone), `Orb/` (ParticleOrb's shaders in Metal), `Intents/` (App Intents for Siri, Shortcuts, Spotlight and the Action button - `AskNova` and the rest, `NovaShortcuts` for Siri's phrases; they run in the app, `Nova.shared.ask` sends an utterance as the app does, the answer is a snippet and Kokoro plays it from the background (`Voice`'s speaker engine: `.playback` + ducking, no microphone), and when Nova asks back `continueInForeground` opens it listening; every intent `.requiresAuthentication`). Out of the front with nothing to do, the app lets its connection rest (`Door.pause`; `hurry` reconnects for Siri, trying each way to the Mac before backing off). `NovaWidgets/` is a WidgetKit extension: the Nova widget (small, medium, Lock Screen) draws `Shared/WidgetState.swift`, which the app writes to a Keychain group it shares with the widgets (`keychain-access-groups` in `Entitlements/`; not an app group, which a free account can't register from the command line), and the Talk to Nova control runs `Shared/TalkToNova.swift`, which iOS opens the app to do (the app sets `TalkToNova.listen`). Widget links are nova://talk and nova://tasks (`Nova.open`). Agents' tasks are Live Activities (`Shared/AgentActivity.swift`, `Nova/Model/LiveActivities.swift`, drawn by `NovaWidgets/AgentActivityWidget.swift`): started from the task board while Nova is in front (iOS allows no other time without push), updated and ended from every `tasks` event, a 15-minute `staleDate`, Stop = `StopAgentTask`, a `LiveActivityIntent` that runs in the app (`StopAgentTask.stop`); setting `phone.activities`, sent in `phone-config`. Nova answering the user is one too (`Shared/NovaVoiceActivity.swift`, `Nova/Model/VoiceActivity.swift`, drawn by `NovaWidgets/NovaVoiceActivityWidget.swift`): started (hidden) as soon as a turn goes to the Mac with Nova in front, `thinking` then `speaking`, ended with the reply (`Nova.answer`: words in and the voice still coming count while the Mac's phase is busy, up to 60 s); away from the front its bars are the voice's spectrum as the speaker engine plays it (`Voice/Spectrum.swift`: a tap on `speakerPlayer`, five bands, the activity updated at most every 0.2 s and animated between - iOS runs no animation of its own in a Live Activity, `symbolEffect` included); Stop = `StopNovaSpeaking` (`Nova.hush`: the playback stops and the Mac gets `cancel`); setting `phone.voiceActivity`. No push on a free account: `Nova.checkIn` runs when iOS allows (Background App Refresh task `dev.nova.phone.check-in`, scheduled on leaving the front): it connects (the reminders and tasks come as on any connection), sends `phone-refresh`, shows the `phone-news` it gets (the Deliverer's news held while the user was away, `forPhone`) as notifications - not a reminder the phone already rang - and answers `phone-news-shown`, so the Mac doesn't say them again (`shownOnPhone`). The voice activity's `relevanceScore` (100) outranks an agent's (0): iOS gives the Dynamic Island to one of an app's activities, and while Nova speaks it's Nova's. The README's iPhone pictures come from the app's scripted session - `-demo <scene>` at launch (`Nova/Model/Demo.swift`: a made-up Mac, events fed to `Nova.handle` as a Mac's would be, no Door, the real pairing untouched) - taken by `npm run readme:phone` (`apps/daemon/src/phone/readme-media.ts`: Simulator screenshots, and the island filmed, since screenshots miss it while it moves; frames by `apps/ios/readme-frames.swift`). Its icon is drawn by `apps/ios/icon.swift` (the Orb of Nova.app's icon, full-bleed, and a grey one for the tinted Home Screen) into `Nova/Assets.xcassets/AppIcon.appiconset`. `npm run phone` builds it, signs it for the certificate's team and installs it on the paired iPhone (`--simulator` for the Simulator).
- `apps/desktop` - React/Vite glass UI (the Orb is a WebGL particle sphere in `ParticleOrb.tsx`). `?shell=mac` = inside Nova.app (no mic/voice of its own, talks to the app via `src/lib/shell.ts`); `?view=hud` = the floating orb (`src/hud/Hud.tsx`). `src-tauri/` is an older, unused shell.
- Presence: `apps/desktop/macos` is Nova.app (Swift, `npm run app` builds/installs it via `apps/daemon/src/shell/install.ts`): one AVAudioEngine with voice processing for mic + Kokoro playback (echo cancellation), Carbon hotkey (`presence.shortcut`, format in `packages/core/src/shortcut.ts` mirrored by `Shortcut.swift`), NSStatusItem menu, non-activating HUD panel, SMAppService login item, hosts the daemon unless one is running or `presence.daemon` is "terminal". It says `shell-hello`; the daemon (`src/shell/presence.ts`) then sends reply audio to it alone and tells windows `voice-owner`. Shortcut: `talk-start` / `talk-end {held}` / `listen-stop` → `Hearing.hold/release/drop` + `NovaBrain.listenNow/stopListening`; held turns reach `NovaBrain.handle(..., 'shortcut')`, addressed without the wake word. The daemon also serves the built window (`src/shell/static.ts`).
- Initiative: `packages/core/src/when.ts` parses times ("at 5", "every weekday at 8:30") in code; skills in `skills/initiative.ts` (remind, reminders, cancel_reminder, snooze/done, brief, missed, task_status, set_project, create_routine); set_timer/cancel_timer use the same reminder service when there is one. The daemon's `src/initiative/` holds the reminder store/scheduler (`~/.nova/reminders.json`, the Reminders app via Nova.app), `Deliverer` (news said only at a good moment: not away/on a call/busy; "while you were away" on return), `Briefing` (+ Open-Meteo `weather.ts`, calendar via Nova.app), `Routines` (settings `routines.<name>`), the task board (`tasks.json`) and `state.json` (current project, last briefing); `index.ts` ties them together. NovaBrain news (timers, agent results) goes through `opts.deliver`; skills may return `needs: 'when'` (Nova asks, the answer completes it) or `handoff` (a brain answers). Nova.app answers `shell-request` (EventKit reminders/calendar, notifications) and sends `shell-context` (locked, camera, idle).
- `doc/` - design docs, always as PDF.
- Rules: never call Jev directly outside `DecisionEngine`; risk tier is declared in code, never inferred from untrusted content; arithmetic/dates/parsing stay in code.
- Git: `develop` is the default branch. Branch from it as `feature/…`, `bugfix/…` or `hotfix/…`, open a PR into `develop`, review it and fix what the review finds, then auto-merge (squash) once CI passes; the branch is deleted. Only `develop` merges into `main` (merge commit), and only when the user asks for a release; each merge cuts `release/v<version>` from `main`. Nobody pushes to `main` or `develop` directly.
